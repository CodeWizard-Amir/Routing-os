# راه‌اندازی اعلان واقعی در Routine OS روی Vercel

این نسخه برای اعلان پس‌زمینه از **Vercel Functions + Upstash QStash + Web Push** استفاده می‌کند. سرور اختصاصی، VPS یا دیتابیس برای اطلاعات برنامه لازم نیست؛ البته باید در Upstash یک حساب QStash بسازی و کلیدهای آن را در Vercel وارد کنی. برنامه‌ها و سوابق همچنان در IndexedDB همان مرورگر باقی می‌مانند.

## معماری و حریم خصوصی

- زمان هر یادآوری آینده به‌عنوان یک پیام زمان‌دار به QStash فرستاده می‌شود؛ اشتراک Push و متن اعلان قبل از ذخیره در صف با AES-256-GCM رمزگذاری می‌شوند.
- در موعد مقرر، QStash یک درخواست امضاشده به Vercel می‌فرستد.
- Vercel با کتابخانه `web-push` پیام رمزگذاری‌شده را به Push Service مرورگر می‌فرستد.
- Service Worker گوشی، حتی وقتی صفحه Routine OS بسته است، اعلان را نمایش می‌دهد.
- دیتابیس برنامه، فهرست کامل فعالیت‌ها، آمار و اطلاعات شخصی به Vercel منتقل نمی‌شوند. Vercel هنگام ثبت یادآوری، اشتراک Push و متن همان اعلان را دریافت و رمزگذاری می‌کند؛ QStash فقط بسته رمز‌شده، زمان تحویل و نشانی API را نگه می‌دارد. کلید رمزگشایی فقط در Vercel است.
- کد دسترسی API در `localStorage` همان دستگاه ذخیره می‌شود و وارد فایل Backup نمی‌شود.

## ۱) نصب وابستگی‌ها

در پوشه اصلی پروژه اجرا کن:

```bash
npm install
```

## ۲) ساخت کلیدهای Web Push

در ترمینال پروژه:

```bash
npx web-push generate-vapid-keys --json
```

دو مقدار `publicKey` و `privateKey` تولید می‌شود. آن‌ها را در جایی امن نگه دار. کلیدها را فقط یک بار بساز؛ با تعویض VAPID key، اشتراک‌های قبلی دستگاه‌ها دیگر معتبر نخواهند بود.

## ۳) ساخت کلید رمزگذاری و کد دسترسی خصوصی

برای رمزگذاری محتوای صف، یک کلید ۳۲ بایتی Base64 بساز:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
```

این مقدار را برای `PUSH_PAYLOAD_ENCRYPTION_KEY` استفاده کن. فقط یک بار بساز و نگه دار؛ با تغییر آن، پیام‌هایی که قبلاً در صف مانده‌اند دیگر رمزگشایی نمی‌شوند.

سپس کد دسترسی API را جداگانه بساز:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

این مقدار برای `PUSH_API_SECRET` است. هر دو مقدار را محرمانه نگه دار.

## ۴) ساخت QStash در Upstash

1. وارد `https://console.upstash.com/` شو.
2. یک QStash بساز یا وارد QStash فعلی شو.
3. از بخش Overview مقدار Token را بردار.
4. از بخش Signing Keys هر دو مقدار Current Signing Key و Next Signing Key را بردار.

این مقادیر فقط در متغیرهای محیطی سمت سرور Vercel قرار می‌گیرند؛ هرگز آن‌ها را داخل کد کلاینت یا Git قرار نده.

## ۵) افزودن Environment Variables در Vercel

به مسیر زیر برو:

`Vercel Dashboard → پروژه Routine OS → Settings → Environment Variables`

این متغیرها را برای **Production** اضافه کن:

| نام متغیر | مقدار |
|---|---|
| `QSTASH_TOKEN` | توکن QStash |
| `QSTASH_CURRENT_SIGNING_KEY` | کلید امضای فعلی QStash |
| `QSTASH_NEXT_SIGNING_KEY` | کلید امضای بعدی QStash |
| `VAPID_PUBLIC_KEY` | publicKey تولیدشده |
| `VAPID_PRIVATE_KEY` | privateKey تولیدشده |
| `NEXT_PUBLIC_VAPID_PUBLIC_KEY` | همان publicKey، دقیقاً بدون تغییر |
| `PUSH_API_SECRET` | کد دسترسی API مرحله ۳ |
| `PUSH_PAYLOAD_ENCRYPTION_KEY` | کلید Base64 رمزگذاری مرحله ۳ |

`VAPID_SUBJECT` اختیاری است؛ اگر تنظیم نشود، آدرس دامنه فعلی سایت به‌عنوان شناسه تماس VAPID استفاده می‌شود.

بعد از ثبت Environment Variables حتماً یک بار **Redeploy** انجام بده تا متغیر `NEXT_PUBLIC_VAPID_PUBLIC_KEY` هم داخل Build کلاینت قرار بگیرد. Route تحویل اعلان سقف اجرای ۳۰ ثانیه دارد؛ Vercel Function را فقط هنگام رسیدن پیام اجرا می‌کند، نه به‌صورت دائمی.

## ۶) اتصال گوشی

1. نسخه جدید سایت را در Chrome باز کن. اگر قبلاً PWA نصب کرده‌ای، برنامه را کامل ببند و دوباره باز کن تا Service Worker جدید فعال شود.
2. از داخل برنامه وارد «تنظیمات» شو.
3. همان مقدار `PUSH_API_SECRET` را در قسمت «کد اتصال اعلان» وارد و ذخیره کن.
4. روی «فعال‌سازی اعلان‌ها» بزن و اجازه Notifications را صادر کن.
5. روی «اعلان آزمایشی» بزن. باید حدود ۲۰ ثانیه بعد یک اعلان دریافت کنی؛ برای این آزمایش صفحه برنامه را ببند.
6. برای هر برنامه، یادآوری دلخواه مثل ۵ یا ۱۰ دقیقه قبل را انتخاب کن.

### iPhone / iPad

در iOS، Web Push برای Web App نصب‌شده روی Home Screen از iOS/iPadOS 16.4 به بعد پشتیبانی می‌شود. ابتدا سایت را از Safari با گزینه Share → Add to Home Screen نصب کن، اپ نصب‌شده را باز کن و سپس از داخل آن اجازه اعلان را صادر کن. صرفاً بازکردن سایت در یک تب Safari کافی نیست.

## محدودیت پلن رایگان

طبق صفحه قیمت‌گذاری فعلی، QStash Free برای پیام‌های Delay حداکثر ۷ روز آینده و تا ۱٬۰۰۰ پیام در روز را شامل می‌شود. هر تلاش ارسال مجدد نیز می‌تواند در مصرف پیام‌ها حساب شود. این پروژه برای حاشیه امن، پیام‌ها را تا ۶ روز و ۲۳ ساعت جلوتر ثبت می‌کند و هنگام بازشدن برنامه، برگشتن به صفحه یا هر ۶ ساعت در زمانی که صفحه باز است، پنجره زمان‌بندی را به‌روز می‌کند.

بنابراین برای دریافت یادآوری‌های بی‌وقفه در بلندمدت، برنامه باید دست‌کم هر چند روز یک بار روی دستگاه باز شود تا هفته بعد هم ثبت شود. اگر برنامه بیش از ۷ روز روی همه دستگاه‌ها بسته بماند، یادآوری‌هایی که هنوز به QStash ارسال نشده‌اند، طبیعتاً قابل ارسال نیستند. این محدودیت از آن‌جاست که برنامه عمداً اطلاعات تکرارهای بلندمدت را در سرور ذخیره نمی‌کند.

## رفع اشکال

- **کد اتصال معتبر نیست:** مقدار `PUSH_API_SECRET` در تنظیمات برنامه باید دقیقاً با Vercel یکی باشد.
- **QStash configuration:** نام و مقدار `QSTASH_TOKEN` و دو Signing Key را بررسی کن؛ سپس Redeploy کن.
- **Push payload cannot be decrypted:** مطمئن شو `PUSH_PAYLOAD_ENCRYPTION_KEY` دقیقاً همان کلیدی است که زمان ثبت پیام استفاده شده؛ این کلید را عوض نکن، مگر اینکه پیام‌های قبلی دیگر لازم نباشند.
- **VAPID key missing:** مقدار `NEXT_PUBLIC_VAPID_PUBLIC_KEY` را هم در Vercel ثبت کن و حتماً Redeploy کن.
- **آزمایش اعلان نمی‌رسد:** در Upstash QStash → Logs وضعیت پیام را ببین. `DELIVERED` یعنی درخواست به Vercel تحویل شده؛ خطای Vercel را در Vercel → Logs بررسی کن.
- **گوشی اندروید:** مطمئن شو اعلان‌های Chrome و اعلان‌های خود PWA از تنظیمات سیستم مجاز باشند و Battery Saver / Background restrictions مانع Push نشده باشند.
- **iPhone:** حتماً PWA را به Home Screen اضافه کن و اعلان را از داخل نسخه نصب‌شده فعال کن. Web Push برای Web App نصب‌شده در iOS/iPadOS 16.4 به بعد ارائه شده است.

## تغییرات فنی این Patch

- API ثبت زمان اعلان: `POST /api/push/schedule`
- API لغو پیام‌های صف: `POST /api/push/cancel`
- دریافت و اعتبارسنجی امضای QStash و تحویل Web Push: `POST /api/push/deliver` (با سقف اجرای ۳۰ ثانیه در Vercel)
- زمان‌بندی مجدد جلسات آینده در بازه امن کمتر از ۷ روز
- لغو یادآوری پس از تکمیل، حذف یا ویرایش جلسه/برنامه
- حذف شناسه‌های مختص هر دستگاه از فایل پشتیبان
- Push Event و Notification Click در Service Worker
